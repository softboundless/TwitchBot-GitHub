# Twitch Bot — настраиваемая копия

Бот для одного или нескольких Twitch-каналов с локальной страницей настроек. Через неё можно заполнить `.env`, выбрать вариант с `!трек` или без него, включить и выключить отдельные команды, настроить игры и автоматические действия.

По умолчанию музыка, автоматический закреп и автоматический разбан выключены. В копии нет готовых токенов, чужих каналов, списков модераторов и игровых сохранений. Ник бота определяется аккаунтом Twitch, который вы авторизуете.

## Быстрый старт

### 1. Подготовьте папку

Установите **Node.js 22 или новее**, распакуйте проект и откройте терминал в папке с `package.json`.

```sh
node --version
npm install
npm run setup
```

Откройте адрес, который появится в терминале: обычно **http://127.0.0.1:8788**. Это локальная панель настройки. Пока она открыта, оставьте терминал работающим. Сам бот этой командой не запускается.

На Windows после установки Node.js можно дважды нажать **`setup.cmd`** в папке проекта: он запустит эту же панель. Затем откройте указанный адрес в браузере.

`setup/index.html` — исходник интерфейса. Его нужно открывать через `npm run setup`: двойной щелчок по HTML не сможет сохранить `.env`.

### 2. Создайте приложение Twitch

1. Откройте [консоль разработчика Twitch](https://dev.twitch.tv/console/apps), подтвердите почту и включите двухфакторную аутентификацию аккаунта.
2. Зарегистрируйте своё приложение. Выберите категорию **Chat Bot** и тип **Confidential**, поскольку эта версия использует Client Secret для обновления токенов.
3. Если форма требует OAuth Redirect URL, укажите `http://localhost:3000`. Бот использует вход по коду устройства и не запускает сервер на этом адресе.
4. Откройте управление приложением, скопируйте **Client ID**, нажмите **New Secret** и скопируйте **Client Secret** в локальную панель бота.

Настройки приложения описаны в [официальной инструкции Twitch](https://dev.twitch.tv/docs/authentication/register-app/); вход по коду — в разделе [Device code grant flow](https://dev.twitch.tv/docs/authentication/getting-tokens-oauth/#device-code-grant-flow).

### 3. Заполните панель

В разделе Twitch укажите данные приложения и логины каналов через запятую, например `my_channel,second_channel`. Первый канал считается основным. Адрес страницы Twitch и символ `#` не нужны.

Выберите **«Без !трек»**, если музыка не нужна. Python, Яндекс-токен и публичный домен в этом варианте не требуются. В разделе команд отключите ненужные пункты для всех каналов или только для выбранного канала. Остальные настройки можно оставить по умолчанию.

Нажмите **«Сохранить .env»**. Файл появится в корне этой копии. Сохранённые секреты при следующем открытии формы не показываются; пустое поле сохраняет прежний секрет. Для удаления используйте отдельную кнопку очистки.

После настройки остановите панель сочетанием `Ctrl+C`. Панель и бот — отдельные программы: изменение `.env` применяется после перезапуска бота.

### 4. Авторизуйте аккаунты

Сначала аккаунт, от имени которого бот будет отвечать:

```sh
npm run authorize -- bot
```

Скрипт покажет код и ссылку Twitch. Откройте ссылку **под аккаунтом бота**, подтвердите доступ и дождитесь сообщения `SAVED`. Если браузер уже вошёл под вашим основным аккаунтом, используйте другой профиль браузера или сначала переключите аккаунт.

Затем авторизуйте владельца каждого канала. Вместо `my_channel` подставьте настоящий логин из настроек:

```sh
npm run authorize -- owner:my_channel
```

Этот код подтверждает **владелец соответствующего канала**. Без его токена не будут работать опросы, прогнозы и смена категории. Можно авторизовать всех по очереди одной командой `npm run authorize` без аргументов. Токены сохраняются в `tokens/` автоматически.

В каждом канале выдайте боту модератора командой Twitch `/mod логин_бота` от владельца канала. Название аккаунта бота не задаётся в `.env`: оно берётся из авторизации.

### 5. Запустите

```sh
npm start
```

Дождитесь подключения к настроенным каналам. Напишите `!пинг` от владельца или модератора: бот ответит `ПОНГ`, если команда включена. `Ctrl+C` останавливает бота. Окно с `npm start` должно оставаться работающим.

Не запускайте одновременно несколько экземпляров с одинаковыми токенами. Для постоянно работающего бота используйте отдельную службу на сервере; пример ниже.

## Как управлять командами

Все переключатели находятся в разделе команд локальной панели. Есть общий список и настройки отдельного канала. Общее отключение имеет приоритет: включить такую команду только в одном канале нельзя, пока она отключена для всех.

| Настройка | Действие |
| --- | --- |
| Вариант «Без !трек» | Отключает музыкальную команду, музыкальный HTTP-мост и запуск музыкального Python-процесса |
| Переключатель отдельной команды | Запрещает её выполнение после перезапуска бота |
| `GAMES_ENABLED` | Включает или полностью отключает игровой модуль |
| `GAMES_CHANNELS` | Ограничивает игры перечисленными каналами; пустое значение — все подключённые |
| `GAMES_DEFAULT_MODE` | Начальный доступ к играм: `off` — администрация, `on` — все, `vip` — администрация и назначенные временные VIP |
| `MUSIC_CHANNELS` | Каналы с `!трек`, если музыка включена; пустое значение — все подключённые |

В чате владелец или модератор также может написать `!откл !пиво` и `!вкл !пиво`. Эти изменения сохраняются отдельно для канала. Команда, запрещённая в `.env`, остаётся запрещённой: чат не может отменить этот запрет. В панели сохранённое отключение из чата отмечено как «Отключено в чате». Чтобы снять его, выберите нужный канал, включите команду и сохраните настройки. Панель снимет и сохранённый запрет из чата; после этого перезапустите бота.

`!вкл` **без аргумента** разрешает игры всем зрителям; `!выкл` возвращает доступ только администрации. `!выклвип` оставляет игры администрации и временным VIP, добавленным через `!добавить ник`. Текущий игровой режим сохраняется между запусками. `GAMES_DEFAULT_MODE` задаёт режим для нового канала; для существующего используйте команды чата.

Все административные команды по умолчанию доступны владельцу и настоящим модераторам соответствующего чата. `MODS` — дополнительный общий список разрешённых логинов. `MODS_ИМЯКАНАЛА` задаёт отдельный список для канала вместо общего; пустой отдельный список убирает дополнительные логины, сохраняя доступ владельца и модераторов. Для стандартной работы эти списки можно оставить пустыми.

Исключения для зрителей: `!трек` доступен всем, когда включён; `!скок` также доступен VIP и подписчикам; игровые команды зависят от игрового режима. Незнакомые и отключённые команды игнорируются.

## Примеры команд

| Команда | Назначение |
| --- | --- |
| `!poll Во что играем? Игра1/Игра2 120` | Опрос на две минуты |
| `!endpoll` | Завершить опрос |
| `!pred Победим? Да/Нет 60` | Прогноз с минутой на ставки |
| `!predstop` / `!predwin 1` / `!predcancel` | Закрыть ставки / выбрать победивший исход / отменить прогноз |
| `!+pred победа Победим? Да/Нет 60` | Сохранить шаблон прогноза |
| `!pred победа` | Запустить сохранённый шаблон |
| `!-pred победа` | Удалить шаблон прогноза |
| `!g Minecraft` | Сменить категорию трансляции |
| `!+g майн Minecraft` / `!g майн` / `!-g майн` | Создать / использовать / удалить шаблон категории |
| `!шаблоны` | Показать сохранённые шаблоны |
| `!скок (100+20)/3` | Калькулятор |
| `!пинг` | Проверка ответа бота |
| `!кд 10` | Общая пауза игровых команд в секундах |
| `!бал`, `!каз 100`, `!пиво`, `!дуэль ник 100` | Примеры игр |
| `!расклад Вопрос` | Ответ через Groq, если задан API-ключ |

Полный список включаемых команд виден в панели. Возможность проведения опросов зависит от статуса Twitch-канала: API опросов доступен партнёрам и компаньонам. [Официальное описание опросов](https://dev.twitch.tv/docs/api/polls/).

## Дополнительные функции

- **Автозакреп:** включите `AUTO_PIN`, выберите каналы и задайте текст для каждого. Бот проверяет закреп и переходы начала/окончания стрима. Длительность самого закрепа определяет Twitch; бот не публикует его непрерывно во время стабильного стрима.
- **Авторазбан:** включайте только для нужных каналов, указав конкретный логин и допустимых авторов бана. Параметр запуска без проверки автора бана по умолчанию отключён.
- **Расклады:** задайте собственный `GROQCLOUD_API_KEY`. Остальные игры не требуют этого ключа. Запросы к выбранному провайдеру могут расходовать его квоту.
- **Музыка:** отдельная инструкция [docs/MUSIC.md](docs/MUSIC.md). Все разрешённые музыкальные каналы одного экземпляра используют один источник текущего трека.

## Где что хранится

| Путь | Содержимое | Загружать на GitHub |
| --- | --- | --- |
| `src/`, `scripts/`, `setup/`, `test/`, `docs/` | Код, интерфейс, проверки и инструкции | Да |
| `.env.example` | Пустой образец настроек | Да |
| `.env` | Ваши настройки и секреты | Нет |
| `tokens/` | Twitch OAuth-токены | Нет |
| `data/fun/<канал>/` | Игры, настройки команд и шаблоны каждого канала | Нет |
| `private/` | Сгенерированный музыкальный userscript с секретом | Нет |
| `.venv-ynison/`, `node_modules/`, `artifacts/` | Локальное окружение и результаты проверок | Нет |

Данные каналов независимы. При обновлении существующей установки сохраняйте её `.env`, `tokens/`, `data/` и `private/`. Для резервной копии они нужны, но хранить такую копию следует отдельно от публичного репозитория.

## Загрузка на GitHub

Создайте пустой репозиторий GitHub. Загружайте **содержимое именно этой папки**, а не родительский каталог рабочего бота. До первого коммита:

```sh
npm test
npm run check:public
git init
git add .
git status --short
```

Убедитесь, что `.env`, `tokens/`, `data/` и `private/` отсутствуют в списке добавленных файлов, затем:

```sh
git commit -m "Initial configurable Twitch bot"
git branch -M main
git remote add origin https://github.com/YOUR_LOGIN/YOUR_REPOSITORY.git
git push -u origin main
```

Замените `YOUR_LOGIN` и `YOUR_REPOSITORY` своими значениями. Файл `.gitignore` уже исключает приватные файлы. Он не удаляет секреты, если вы раньше принудительно добавили их в историю: в такой ситуации сначала отзовите секреты и очистите историю. Для проверки чистого распространяемого архива есть `npm run check:public -- --strict`.

Можно вместо Git загрузить чистые файлы через интерфейс GitHub; `.gitignore` не фильтрует файлы при ручном выборе в браузере. Сам бот не запускается на GitHub Pages: ему нужен Node.js-процесс на компьютере или сервере.

## Постоянная работа на Linux

Установите Node.js 22+, разместите эту копию в отдельном каталоге и выполните настройку и авторизацию. Если панель запущена на сервере, откройте к ней локальный SSH-туннель:

```sh
ssh -L 8788:127.0.0.1:8788 USER@YOUR_SERVER
```

В этой SSH-сессии перейдите в каталог бота и запустите `npm run setup`, затем откройте `http://127.0.0.1:8788` на своём компьютере. Не публикуйте локальную панель через открытый reverse proxy.

Для автозапуска создайте отдельную systemd-службу со своим непривилегированным пользователем. Пример `/etc/systemd/system/twitch-bot.service`:

```ini
[Unit]
Description=Configurable Twitch Bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=twitchbot
WorkingDirectory=/opt/twitch-bot
ExecStart=/usr/bin/node --env-file=.env src/index.js
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Сначала создайте пользователя `twitchbot`, предоставьте ему доступ к каталогу и проверьте путь к Node командой `command -v node`. Исправьте пример под своё расположение. После этого:

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now twitch-bot
sudo systemctl status twitch-bot
journalctl -u twitch-bot -f
```

После изменения `.env` выполните `sudo systemctl restart twitch-bot`. Этот пример предназначен для отдельной установки: он не меняет существующие службы или настройки чужого сервера.

Если бот не запускается или не отвечает, начните с [ADMIN.md](ADMIN.md).
